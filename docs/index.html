Long-Horizon Episode Gallery

Long first-person cooking, packing and household episodes from the InteractiveWorld simulator, longest first. Each row is one TaskPack. The video replays what the person did before asking, then the oracle's actions. The transcript shows the request and the scripted oracle advice. Status pills report the oracle replay check and the full oracle-verbal run through the interaction runtime.

Non-Markov tasks. In most tasks, everything the Assistant needs is still in view when it acts. The -NM variants take the labels away once they have been read: a shipment manifest, carton sizes read before a phone call, a roast timing sheet, a lunch ticket. The right next step then depends on what was seen earlier, not on the current frame. Each one is paired with its unchanged base task as a Markov control. The scripted oracle already knows the plan, so these runs show only that each task is solvable and scored correctly. Measuring memory needs a model as the Assistant.

What running them found

Every task was replayed by its oracle and run through run_taskpack --assistant oracle-verbal on one RTX 4060 laptop under Windows. These findings belong to the release, not to the gallery tasks. All but the physics ones reproduce offline.

  • oracle-verbal cannot run WATCH tasks. Under --assistant oracle-verbal the Human is always scripted (human_policy is fixed to auto), and the scripted Human acts only after the Assistant speaks. So it never performs the opening of a WATCH task: the person stands still and the episode ends with eval_valid=false. WATCH cards show oracle-verbal as n/a. Their oracle replays pass.
  • GUIDE-17001: handoff parser. Two of its four oracle lines stall. Line 1 ends "do not use that sponge on the electronics or paper", which the parser reads as a wipe of the paper form. Line 2 never mentions returning the cloth, although its actions do. Spelling each wipe out ("wipe the mug with the blue sponge") parses into the right steps but is still rejected by the completion matcher. GUIDE-17001-REWORDED passes the check.
  • GUIDE-14004: handoff parser. The parser reads "not the tomato" in the third oracle line as part of the Stir step, so the scripted person's "That's done" is never accepted. preflight_guide.py finds this offline. GUIDE-14004-REWORDED rewords the line and passes.
  • NARRATE-87016 and ASK-87022: process scoring. In both, every action succeeds and the world goal is met, but strict success never comes. _process_commands_equivalent forgives an optional @place_spot only for PutOn, not PutInside, and a required bare [Drop] matches nothing but itself, so the oracle's [PutOnFloor] fails it. preflight_process.py predicted both before any GPU time. A two-rule patch is in the repo, unapplied, because it changes benchmark scoring.
  • The public CLI cannot replay runtime commands. Action.parse rejects @place_spot and container-space instance (0), and dropping them changes what runs. faithful_simulator.py sends only those commands through the release's own unvalidated path. With it, the ORCHESTRATE-16013 replay that had failed now passes.
  • Missing label font on Windows. The label generator looks for DejaVu at a Linux path, then in a vendored fonts/ folder that the release does not ship. Missing both, it falls back to PIL's bitmap font, with 8 px glyphs, and every label-reading [LookAt] fails as UNREADABLE_LABEL. Pointing it at the DejaVu copy that matplotlib ships fixed GUIDE-109009, GUIDE-110011 and GUIDE-14015. Videos for the cooking tasks, GUIDE-102000, GUIDE-110011, GUIDE-14015 and ASK-14011 were rendered before the fix, so their labels may be unreadable.
  • Windows physics. Some PutInside and PutOn placements do not settle (milk cartons in order boxes, plates on counters), so a stage can fail in one run and pass in the next. ORCHESTRATE-16013's knife returns settle about 13 cm high under oracle-verbal.
  • Packing ports. These never built. The error blamed the packing boxes, but the release's own offline siting predictor (wrapped in preflight_siting.py) showed the real cause. The person's standing spot at Rs_int's living-room breakfast_table, which sits among five chairs, is never on walkable floor, so every layout was rejected. Rebinding that support to the room's bottom_cabinet lets five of the six ports pass siting. Their "never pack" rules were also in a shape the stage cannot parse, and have been rewritten as not_inside constraints. PACK-BEACH-HOLIDAY and PACK-WINTER-VISIT now build, but the first item will not fit inside box_1 (NO_FREE_PLACEMENT). The other three still fail to build: the start room has no spot at least 2.2 m from the request note. PACK-MOVE-OUT needs five boxes, which no room layout of Rs_int holds. Garment scales below 0.5 were also rejected and were clamped.
